# Inference-time methods for small/open-weight coding agents (focus Jun-Nov 2026)

Compiled 2026-11-21. Complements `literature_review.md`; nothing from that file is repeated except where a new number changes the decision.

## How to read this

- **Verification is search-extract only.** Direct fetches of arxiv.org, alphaxiv.org, ai.google.dev and blog hosts all failed (hosts not in this session's network allowlist). No full paper was read. Every number below appeared in a search-engine extract of the cited page; where the extract came from a secondary site this is flagged "secondary".
- Verification labels: **T** = title/ID only; **A** = abstract-level content seen; **N** = numbers seen in extract of the primary page; **N2** = numbers seen only via a secondary source.
- None of these papers tests Gemma 4 31B under 30 calls / 5 min / 14k compaction. Every "Use" line is a **Hypothesis** for our setting unless stated otherwise.
- Failure modes: (a) no edit at all, (b) right file, wrong/incomplete fix (esp. >20 lines), (c) multi-file missed, (d) timeouts.
- Not found despite searching: any Kaggle discussion/notebook findings for this competition; any Gemma 4 SWE-bench number in the Gemma 4 Technical Report (arXiv 2607.02770, T); any controlled temperature sweep for agentic coding; any controlled prompt-only "remaining budget shown" ablation; a 2026 study of few-shot trajectory demos in the system prompt for small models (one 2025 paper surfaced with a "+29 points from one demonstration" extract, but I could not capture its title or benchmark, so it is not cited).

## 6. Skill script sketches (all untested; Hypotheses)

**S1 `sym.py` - symbol-level read and replace (CODESTRUCT / SWE-Edit).**
- `python sym.py show FILE Class.method` prints that function with line numbers (uses `ast`; start = first decorator line, end = `end_lineno`).
- `python sym.py replace FILE Class.method /tmp/new.py` replaces those lines with the content of `/tmp/new.py`, runs `py_compile`, and on a syntax error restores the original and prints `ERROR: syntax at line N -> NEXT: fix /tmp/new.py and rerun`. On success prints `OK replaced L120-L158 (+41/-39)` and `git diff --stat`.
- Flow for the model: `write_file /tmp/new.py` (full new function, original indentation) then one `run_command`. Two calls, no exact-match requirement, no long old_string.

**S2 budget ticker (BAGEN / More with Less / Steer).**
- Every skill script sources a helper that stores the first-invocation time in `/tmp/.t0`, increments `/tmp/.n`, and appends one line to its output: `[budget] 140s of 300s used; edits so far: 0 files. NO EDIT YET -> edit now. Unsubmitted work is lost.` (`edits so far` from `git diff --name-only | wc -l`).
- After 200 s or once a diff exists and lint passes: `-> call submit_patch now`.
- Wall-clock is exact only if a skill runs at call 1, so make the first prescribed call a skill (e.g. the batched grep).
- This re-enters context after every compaction because it rides on fresh tool results.

**S3 `ckpt.sh` (Coherence Collapse / Termination Lag).** `git diff > /tmp/best.patch` when lint passes; `ckpt.sh restore` does `git checkout . && git apply /tmp/best.patch`. Fold into the existing lint gate so it costs no extra call.

**S4 `impact.sh SYMBOL` (multi-hunk papers).** `grep -rnw --include='*.py' --exclude-dir=tests --exclude='test_*' SYMBOL . | head -15`, plus other definitions with the same name (`grep -rn "def SYMBOL\b"`), plus files importing the edited module. Prompt: "For each line listed, answer in one word whether it needs the same change; edit those that do." One call.

## 7. Ranked experiments

Run each against the current best config, >= 3 runs, paired per task (see randomness item; 36 tasks give ~6.7 pp SE per run).

1. **Symbol-replace skill + edit-mode rule (S1).** "<= 8 changed lines: edit_file. Larger, or after one edit_file failure: write new function to /tmp/new.py and `sym.py replace`." Mechanism: removes exact-match and long-argument failures; makes >20-line fixes one unit. Targets (a), (b). Evidence: CODESTRUCT (empty patches 46.6% -> 7.2% on a weak model), SWE-Edit, AiXapply. Risk: model emits wrong indentation or a truncated function; script must refuse and restore. Gains may be small if Gemma's failures are reasoning-limited (CODESTRUCT's Qwen3-8B case).
2. **External budget ticker + hard milestones (S2).** "First edit by call 10; submit by call 22 or 200 s." Mechanism: the model cannot estimate its own remaining budget (BAGEN); an external counter in every tool result can. Targets (a), (d). Risk: wall-clock estimate is off if the first call is not a skill; premature low-quality edits (acceptable: a wrong patch scores the same as no patch).
3. **Stop at first validated edit + checkpoint guard (S3).** "After the first edit passes lint and one targeted check, submit. Re-open a hunk only on a failing output." Mechanism: 38-82% of successful runs are right at the first edit; later steps mostly burn budget and sometimes undo the fix. Targets (a), (d), partly (b). Risk: loses the cases needing a second hunk; pair with experiment 6 so the one allowed follow-up step is the impact sweep.
4. **Sampling A/B: model-card default (T 1.0, top_p 0.95, top_k 64) vs current, crossed with a reduced thinking budget (e.g. half the current).** Mechanism: card says one setting for all uses; loops are reported at every temperature; higher effort lengthens trajectories. Targets (a), (d). Risk: more malformed tool arguments at T 1.0 (one community report); high run-to-run noise, needs the most repeats.
5. **Empty-argument tool audit and hardening.** Grep our 36 traces for failed `get_status` / `submit_patch` calls and for repeated identical failed calls; add literal call examples; replace `get_status` with `git status --short`; rule "after a tool error the next call must differ". Mechanism: malformed calls cluster on zero-argument tools; models retry identical bad payloads. Targets (a). Risk: none beyond prompt length; may find nothing at 31B.
6. **Impact sweep after the first edit (S4), tests excluded.** Mechanism: undershoot / partial-fix convergence; one call lists sibling definitions and callers. Targets (c), (b). Risk: over-editing unrelated call sites; costs 1-3 calls, conflicts with experiment 3 unless capped at one sweep.
